GPUノードは、vLLM のようなモデルサーバーが NVIDIA の GPU でそうするように、借りた GPU で推論を提供します。

## どこに置くか

- AI プロンプトがトラフィックの大きな割合を占め、[LLM API](/components/llm)の請求が台帳の大きな一行になっているときに置きます。[モデルサービング](/research/model-serving)でアンロックします。
- 負荷が遊んでいるか跳ねるときは省きます。GPUノードは忙しくてもそうでなくても動くすべての秒に課金され、LLM API よりトークンあたり安いのは忙しく動き続けている間だけです。
- 安定した AI の負荷に合わせてサイズを選び、スパイクは LLM API に任せます。

## 仕組み

容量は秒間トークンで測り、各 AI プロンプトは決まった数のトークンを使います。サイズを 1 段上げるごとに GPU が 2 倍になり、容量と支出も 2 倍になります。推論の呼び出しはアプリサーバーから届き、何も先へ流しません。[モデル推論](/glossary/model-inference)を参照してください。

新しい GPUノードも再起動した GPUノードもコールドで始まります。モデルを読み込み、温まるまで容量の何分の 1 かで提供します。

## オプション

::Options{id="gpu"}

- **GPU**: T4 は安くて遅いです。A100 はバランス型です。H100 はトークンあたり最も安く、最も手に入りにくいです。種類を変えるとノードが再起動します。
- **モデル**: 大きなモデルほどプロンプトあたりの稼ぎが多く、処理できる数は少なくなります。重み、精度、バッチのアテンションキャッシュは GPU のメモリに収まる必要があります。収まらないとノードは読み込み中に殺され、すべてのプロンプトが `oom` で失敗します。精度を下げる、モデルを小さくする、バッチを小さくする、GPU を大きくするのいずれかで収まります。モデルを変えると重みを読み込み直します。
- **精度**: 低い精度はより速く提供し、メモリも使わず、答え 1 つあたりの価値は下がります。[量子化](/research/quantization)が必要です。
- **バッチ**: 大きなバッチはより多くのプロンプトを処理し、最初のトークンまでの時間を上げます。[continuous batching](/research/continuous-batching)はスループットを保ち、増えたレイテンシをなくします。[GPU 上でゲートウェイの後ろに置く LLM](/patterns/llm-behind-a-gateway-on-gpus)を参照してください。

## どう壊れるか

- 過負荷になるとプロンプトを捨てます。AI プロンプトは価値の高い種別なので、売上が早く減ります。
- 遊んでいると、金を燃やします。

### [GPU不足](/incidents/gpu-shortage)

- **兆候:** GPUノードが灰色になり、そこへ送ったプロンプトが失敗します。H100 はそれが終わるまで手に入りません。
- **今すぐ:** プロンプトの行き先を作るため、アプリサーバーから [LLM API](/components/llm)をリンクするか、より小さな種類の GPUノードを置きます。回収されたノードを早く戻す方法はありません。最大 120 シミュレーション秒で戻ります。
- **防ぐ:** [ホスト型モデル](/research/hosted-models)をリサーチして LLM API をリンクしたままにします。不足を許容できないときは H100 を避けます。

### [インスタンス障害](/incidents/instance)

- **兆候:** GPUノードのカードが灰色になり、吹き出しに「この VM の下のホストが死にました。請求は続きます。」と出ます。そこへ送ったリクエストは行き場所を失います。
- **今すぐ:** ノードを選んで**置き換え**をクリックします。資金がかかり、コールドで戻ります。
- **防ぐ:** 2 つ目の GPUノードを動かし、[LLM API](/components/llm)をリンクしたままにしてプロンプトの行き先を保ちます。ノードはコールドで戻ります。

### [ゾーン障害](/incidents/zone)

- **兆候:** 1 つのゾーンのすべてのノードが一斉に灰色になり、GPUノードも一緒に落ちます。
- **今すぐ:** ゾーンを早く戻す方法はありません。**フェイルオーバー**は**スタンバイ**を昇格しますが、このコンポーネントはスタンバイを持たないので、最大 120 秒で自然に終わります。
- **防ぐ:** [マルチゾーン](/research/multi-az)をリサーチし、同じコンポーネントのコピーを 2 つ目のゾーンに保ちます。

### [リージョン障害](/incidents/region)

- **兆候:** 1 つのリージョンのボードが灰色になり、そこにある GPUノードが落ちます。
- **今すぐ:** バナーで**フェイルオーバー**を押します。[マルチゾーン](/research/multi-az)と 2 つ目の開いたリージョンが必要で、最も近い別のリージョンでノードをコールドで、置き換え 1 回分の値段で立ち上げ直します。そうしなければインシデントが終わったときに戻ります。カタログでは 180 シミュレーション秒、エラーバジェットが効いてからは 60 秒です。
- **防ぐ:** [マルチリージョン](/research/multi-region)をリサーチし、2 つ目のリージョンにコピーを保ち、[GeoDNS](/research/geo-dns)を追加してユーザーをそこへ送ります。

## ヒント

- 安定した負荷には GPUノード、スパイクには LLM API を動かします。
- 不足を許容できないときは H100 を避けます。
