APIゲートウェイは、Kong、AWS API Gateway、Apigee のように、すべての API 呼び出しがサービスに届く前に通る 1 つの玄関です。

## どこに置くか

- 1 種類のアプリサーバーですべての種別を処理できず、ページビューと API 呼び出しを別のサーバー群へ届けたいときに置きます。
- WAF で追い返さずに、バーストや濫用するクライアントからサービスを守りたいときに置きます。[APIゲートウェイ](/research/api-gateway)でアンロックします。
- API のトラフィックを見て上限をかけられる場所を 1 つ持ちたいときに置きます。
- ボットのフィルターとしては省きます。レート制限は量に上限をかけるだけで、ボットと買い物客を見分けないので、ボットが問題なら [WAF](/components/waf)はやはり手前に置きます。

## 仕組み

レート制限がノードを毎秒のリクエスト数で制限し、それを超えたリクエストはサービスに届かず `throttled` で失敗します。オフにするとすべてを通します。[ユーザー](/components/users)の後に置かれ、各リクエスト種別を経路表が与えるリンクへ送り、自分の 1 ホップを加えます。その経路表が、設計を種別で分ける方法です。`page` は描画用に作ったサーバー群へ、`login` は止まらないサーバーへ、`media` は CDN へ送ります。[レート制限](/glossary/rate-limiting)と、今も必要とする[トークンバケット](/glossary/token-bucket)を参照してください。

稼働秒ごとに課金するほかのすべてのコンポーネントと違い、ゲートウェイはリクエストごとに課金します。量が少なければ安く、多ければ高く、請求の Requests の行になります。価格はマネージドサービスの実ドルの料金なので、時代のコスト指数はそれを掛けません。サイズは 1 つで、自分自身の一定の容量があるので、それを超えた設計は容量が一定のほかのノードと同じくゲートウェイでリクエストを捨てます。

## オプション

::Options{id="gw"}

- **経路**: 各リンクが運ぶリクエスト種別。オフにするまで、すべての種別がすべてのリンクに乗るので、`login` に設定したリンクはログインだけを運び、ほかは運びません。
- **レート制限**: ゲートウェイが通す毎秒のリクエスト数。超えるとリクエストはサービスに届かず `throttled` で失敗します。オフはすべてを通します。
- **バースト**: 「一定の上限」は上限を超えたすべてのリクエストを拒みます。トークンバケットは小さな予備を保つので、短いバーストは丸ごと通り、長期的な平均は保たれます。[レート制限](/research/rate-limiting)が必要です。
- **認証**: 「エッジで認証」は各トークンをゲートウェイで 1 回検証し、後ろのサービスはチェックを省きます。「サービスで確認」は検証を各サービスに任せます。
- **合流**: 同時に飛んでいる同一の読み取りをまとめます。ゲートウェイが忙しいほど、節約が増えます。

## どう壊れるか

- 需要を下回る上限は実際のユーザーを絞り、絞られたリクエストは何も稼がないので、設定する上限は望むトラフィックの余地を残す必要があります。
- 自分の容量を超えると、レート制限の設定に関係なくリクエストを捨てます。
- すべての手前にある単一のホップなので、過負荷や設定ミスのあるゲートウェイはすべてのリクエスト種別を一度に失敗させます。

### [インスタンス障害](/incidents/instance)

- **兆候:** APIゲートウェイのカードが灰色になり、吹き出しに「この VM の下のホストが死にました。請求は続きます。」と出ます。そこへ送ったリクエストは行き場所を失います。
- **今すぐ:** ノードを選んで**置き換え**をクリックします。資金がかかり、コールドで戻ります。
- **防ぐ:** 死んだホストを飛ばす[ロードバランサー](/components/lb)の後ろに 2 つ目のコピーを動かします。[ロードバランシング](/research/load-balancing)と[ヘルスチェック](/research/health-checks)でアンロックします。

### [証明書の期限切れ](/incidents/certificate)

- **兆候:** **証明書の期限切れ**のバナーが出て、APIゲートウェイを通るすべてのリクエストが、ほかの TLS ノードと同じく失敗します。
- **今すぐ:** バナーの**更新**をクリックします。
- **防ぐ:** [証明書の自動化](/research/cert-automation)をリサーチし、[シークレットと証明書](/components/pki)のノードを置きます。証明書が切れる前に更新します。

### [リージョン障害](/incidents/region)

- **兆候:** 1 つのリージョンのボードが灰色になり、そこにある APIゲートウェイが落ちます。
- **今すぐ:** バナーで**フェイルオーバー**を押します。[マルチゾーン](/research/multi-az)と 2 つ目の開いたリージョンが必要で、最も近い別のリージョンでノードをコールドで、置き換え 1 回分の値段で立ち上げ直します。そうしなければインシデントが終わったときに戻ります。カタログでは 180 シミュレーション秒、エラーバジェットが効いてからは 60 秒です。
- **防ぐ:** [マルチリージョン](/research/multi-region)をリサーチし、2 つ目のリージョンにコピーを保ち、[GeoDNS](/research/geo-dns)を追加してユーザーをそこへ送ります。

## ヒント

- ピークが分かるまで上限はオフにし、そのあと提供したいピークより少し上に設定します。
- レート制限だけでなく Requests の行も見ます。リクエストごとの価格はトラフィックとともに増えるからです。
