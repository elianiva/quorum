サービスメッシュは Istio と Linkerd を指します。すべてのサービスの隣に置く**サイドカープロキシ**です。

## どこに置くか

- アプリサーバーとワーカーが多すぎて、リンクごとの設定を管理しきれなくなったときに置きます。
- リトライストームが痛手になっているときに置きます。
- データベースには省きます。データベースはサイドカーを持つサービスではありません。

シリーズ B で[サービスメッシュ](/research/service-mesh)として 20,000 ◇ で、[コンテナオーケストレーション](/research/containers)のあとにアンロックします。[Kubernetesクラスター](/components/cluster)と同じトレードオフです。自動化はある規模から元が取れ、現実の運用コストもかかります。

## 仕組み

実際の製品ではプロキシがサービスと同じポッドに座り、そのネットワーク呼び出しを引き受けます。アプリサーバーとワーカーをリンクします。サイドカーがポッドに乗るので、先に [Kubernetesクラスター](/components/cluster)で動いている必要があります。それぞれにサイドカーが付き、そこから出るすべてのリンクが変わります。

| 与えるもの                                                      | かかるもの                                                      |
| --------------------------------------------------------------- | --------------------------------------------------------------- |
| 即座のリトライと、失敗で開くサーキットブレーカー                | メンバーの CPU の 5%                                            |
| リンクごとのメトリクスと、監視するトラフィックのインサイト +20% | すべてのホップに +1 ms                                          |
| サービス間の相互 TLS                                            | メンバーの支出の 5%（サイドカーの取り分）                       |
|                                                                 | プラットフォームの開発時間 0.5 人、またはプラットフォームチーム |

リトライとブレーカーは独自のリサーチを必要としません。サイドカーが代わりに動かします。プレイヤーが自分のポリシーを設定したリンクはそれを保ちます。メッシュは上書きではなく既定だからです。1 ms、5%、20% はメッシュが使う数値です。

## どう壊れるか

- **素朴なリトライは増幅する。** 失敗している依存先は失敗した呼び出しを最大 3 回まで受け直します。悪い日にはそれがリトライストームになり、メッシュもその一因です。
- **ブレーカーは真実を隠す。** 開いている間はリンクが早く失敗して何も送らないので、それに依存する呼び出しは遅いのではなく拒否として失敗します。
- **5% は常に払う。** サイドカーはトラフィックが重くても軽くても箱の取り分を食い、メッシュはそれを自分の行で請求します。
- **1 ms はホップごと。** 6 回の呼び出しをするチェックアウトは、仕事のうえに 6 ms を払います。
- **プラットフォームの開発時間。** 各メッシュは、プラットフォームチームが運用しない限り、プロダクトチームからエンジニア 0.5 人を取ります。

### [リージョン障害](/incidents/region)

- **兆候:** 1 つのリージョンのすべてのノードが一斉に灰色になり、そのリージョンのボードも一緒に灰色になります。
- **今すぐ:** バナーで**フェイルオーバー**を押します。[マルチゾーン](/research/multi-az)と 2 つ目の開いたリージョンが必要で、最も近い別のリージョンでノードをコールドで、置き換え 1 回分の値段で立ち上げ直します。そうしなければインシデントが終わったときに戻ります。カタログでは 180 シミュレーション秒、エラーバジェットが効いてからは 60 秒です。
- **防ぐ:** [マルチリージョン](/research/multi-region)と [GeoDNS](/research/geo-dns)をリサーチし、2 つ目のリージョンでコピーを動かします。

## ヒント

- メッシュはすべてのノードではなく、最も互いを呼ぶサービスに置きます。
- [サーキットブレーカー](/research/circuit-breakers)をリサーチすると、リンクが自分のブレーカーとリトライの方針を設定できます。そのときメッシュが与えるのはメトリクスと 1 ミリ秒だけです。
- インサイトの行を見ます。アナリティクスがすでにサンプリングしているサービスにメッシュを置くと 20% 多く稼げ、それがサイドカーの分を賄います。
