アプリサーバーは、自分のコードを動かす仮想マシンを指します。

## どこに置くか

- カードが CPU、ワーカー、メモリのいずれかがほぼ満杯を示し、p99 が上がるときに、コピーを足すかサイズを 1 段上げます。
- 2 つ目のコピーの前に、手へ[ロードバランサー](/components/lb)を置きます。
- CPU が低いのに上限がワーカーなら、先にバックエンドを直します。箱がバックエンドを待っているからです。[ボトルネックを見つける](/guides/find-the-bottleneck)を参照してください。

## 仕組み

ページビューとボットには自分で答え、ほかのすべてのリクエスト種別をバックエンド呼び出しに変えます。読み取りと書き込みのクエリ、認証コール、タスク、請求などです。容量はインスタンスの種類と、[ランタイム、そしてフレームワーク](/runtimes)で決まります。4 つの上限のうち最も厳しいものが決めます。CPU、ワーカーのスロット、メモリ、ネットワークです。

リクエストは各バックエンド呼び出しを待つ間、ワーカーのスロットを占有します。そのため、遅いデータベースは、待つ間ワーカーを占有するランタイムの容量も下げます。これが[リトルの法則](/glossary/littles-law)です。

ガレージの箱は同じマシンで Postgres を動かしています。それを[データベース](/components/database)、[コネクションプーラー](/components/pooler)、[キャッシュ](/components/cache)にリンクすると、Postgres は箱から恒久的に移ります。バースト可能な箱は遊んでいる間に CPU クレジットを稼ぎ、尽きると絞られます。

## オプション

::Options{id="server"}

### スタック

スタックは言語、そのランタイム、フレームワークです。箱が仕事をどう分けるか、各リクエストがどれだけ速く走るか、各プロセスが保持するメモリ、ランタイムが接続を開いたままにできるかを決めます。

- **ランタイム**: コードを動かすサーバー。それぞれがリクエストごとのプロセス、スレッドプール、イベントループといったモデルを使い、そのモデルがリクエストがバックエンドを待つしかたを決めます。[ランタイム](/runtimes)を参照してください。
- **フレームワーク**: ランタイムの周りのライブラリ。すべてのリクエストに CPU とメモリを加え、その代わりに速さを買います。選択肢には、そのランタイムの言語のフレームワークが並びます。
- **プールサイズ**: リクエストを処理するワーカープロセスの数。リクエストは各バックエンド呼び出しを待つ間 1 つのスロットを占有するので、遅いデータベースは CPU が遊んだままプールを埋めます。コントロールの隣の数字は、箱の RAM に何人分のワーカーが収まるかを示します。超えると箱はスワップし、やがてプロセスを殺します。
- **プロセスマネージャー**: PHP-FPM はワーカープロセスのプールを保ち、プロセスマネージャーがそのうちどれを動かし続けるかを決めます。静的はプール全体を常駐させるので、どのリクエストも fork を待たず、箱は遊んでいる間もそのメモリを保持します。動的は忙しいワーカーと予備 2 つを保つので、バースト時に一部のリクエストが少しの間 fork を待ちます。オンデマンドは忙しいワーカーだけを保つので、遊んでいる RAM は最も少なく、待つリクエストは増えます。RAM に余裕があるなら静的、大半の設計には動的、メモリが上限でテールが待てるならオンデマンドを選びます。
- **ワーカーを再起動**: ときどき各プロセスを再起動します。プロセスが尽きる前にメモリリークに上限をかけ、再起動のたびにコールドから始まります。リクエストの間もメモリを保つランタイムではオンにします。
- **圧縮**: よく縮む応答に Gzip をかけます。サイズと、課金されるエグレスと、ユーザーに届くまでの時間を削り、その代わりに 1 つごとに CPU がかかります。アップロードとメディアは縮みません。
- **サービス**: ノードが属するサービス。アプリが複数のサービスに分かれた時点で現れます。

### ガベージコレクション

- **コレクター**: Java ランタイムのガベージコレクター。G1 は停止とスループットのバランスを取ります。Parallel は少し速く、より長く止まり、メモリは少し少なく済みます。ZGC はスループットと多くのメモリと引き換えに停止を極小に保ちます。p99 の跳ねが CPU より痛いなら ZGC を選びます。
- **GOGC**: Go ランタイムの回収目標。低い値はより頻繁に回収するので、メモリは小さく保たれ CPU はコレクターへ行きます。高い値はその逆です。どちらでも Go は長い停止なしに回収します。

### 過負荷

- **間引き**: [優先度付きロードシェディング](/patterns/load-shedding)は、満杯のノードに、価値の低い種別からまとめて落として線の下に戻るまで答えさせます。既定の「均等に落とす」は、種別をまとめてではなく、どの種別からも一部を拒みます。残した種別は速いままで、落としたものはエラーとして数えられます。
- **デグラデーション**: [グレースフルデグラデーション](/patterns/graceful-degradation)は CPU を最も食う種別から先に落とすので、安くて量の多い種別はレイテンシを保ちます。両方をオンにしたノードは先にデグラデーションします。
- **自分の書き込みを読む**: 書き込みの後に続く読み取りをプライマリへ送るので、遅れたレプリカが古いデータで答えることができません。[自分の書き込みを読む](/patterns/read-your-writes)を参照してください。

### フィード

- **フィード**: アプリサーバーがフィードをどう提供するか。プルはユーザーがフォローするアカウントを読み取り時に統合します。プッシュはフォロワーごとのタイムラインにコピーを書きます。プッシュは[ハイブリッドファンアウト](/research/hybrid-fanout)でハイブリッドになります。[書き込み時と読み取り時のファンアウト](/patterns/fan-out-on-write-and-on-read)を参照してください。

## どう壊れるか

- 過負荷になると、リクエストを並べ、やがて捨てます。
- RAM が少なすぎる箱はスワップし、RAM に対して大きすぎるプールは殺されます。

### [インスタンス障害](/incidents/instance)

- **兆候:** アプリサーバーのカードが灰色になり、インスペクタに「この VM の下のホストが死にました。請求は続きます。」と出て、そこへ送ったリクエストは行き場所を失います。
- **今すぐ:** インスペクタの**置き換え**を押し、値段を払います。コールドで戻ります。
- **防ぐ:** 2 つ目のコピーを動かします。[ロードバランシング](/research/load-balancing)がコピーをロードバランサーの後ろに置き、[ヘルスチェック](/research/health-checks)が死んだホストを飛ばします。クラスターの中のコピーは自分で再スケジュールされます。

### [ゾーン障害](/incidents/zone)

- **兆候:** 1 つのゾーンのすべてのノードが一斉に灰色になります。
- **今すぐ:** ゾーンを早く戻す方法はありません。**フェイルオーバー**は**スタンバイ**を昇格しますが、このコンポーネントはスタンバイを持たないので、最大 120 秒で自然に終わります。
- **防ぐ:** [マルチゾーン](/research/multi-az)をリサーチし、ゾーン設定でコピーを別のゾーンに置きます。

### [リージョン障害](/incidents/region)

- **兆候:** 1 つのリージョンのすべてのノードが一斉に灰色になり、そのリージョンのボードも一緒に灰色になります。
- **今すぐ:** バナーで**フェイルオーバー**を押します。[マルチゾーン](/research/multi-az)と 2 つ目の開いたリージョンが必要で、最も近い別のリージョンでノードをコールドで、置き換え 1 回分の値段で立ち上げ直します。そうしなければインシデントが終わったときに戻ります。カタログでは 180 シミュレーション秒、エラーバジェットが効いてからは 60 秒です。
- **防ぐ:** [マルチリージョン](/research/multi-region)と [GeoDNS](/research/geo-dns)をリサーチし、2 つ目のリージョンでコピーを動かします。

### [メモリリーク](/incidents/leak)

- **兆候:** カードのインスペクタに「メモリが増えています: N GB 漏れています。」と出ます。放置するとプロセスはメモリを使い果たし、コールドで再起動します。
- **今すぐ:** インスペクタの**再起動**を押します。漏れたメモリを解放し、コールドで戻ります。
- **防ぐ:** **ワーカーを再起動**（定期的な再起動）をオンにするか、メモリリークを直すタスクを行うか、PHP-FPM のように状態を持たないランタイムで動かします。[メトリクス](/research/metrics)と[アラート](/research/alerting)をリサーチして早く気づきます。

### [イベントループのブロック](/incidents/loop)

- **兆候:** `login` のような CPU の重い種別がイベントループを占有するので、そのサービスが答えるすべての種別で p99 が上がります。
- **今すぐ:** バナーの**ログインを移す**を押します。イベントループのアプリサーバーの手前に [APIゲートウェイ](/components/gw)があり、そのゲートウェイからイベントループを持たないランタイムの別のアプリサーバーへリンクがある必要があります。するとゲートウェイは `login` をそこへだけ送り、ループに届くログインがなくなるとインシデントは終わります。それがなければ最大 35 秒で自然に終わります。
- **防ぐ:** [libuvスレッドプール](/research/libuv-pool)と[マネージドID](/research/auth-provider)をリサーチします。重い仕事をループから外します。

### [GCポーズ連発](/incidents/gc-storm)

- **兆候:** ヒープが RAM の 90% を超えたガベージコレクター付きのランタイムで、p50 は普通のまま p99 が跳ねます。
- **今すぐ:** インスペクタの**再起動**を押します。再起動がヒープをきれいにします。
- **防ぐ:** 箱により多くの RAM を与えるか、**コレクター**の欄で Java を [ZGC](/research/zgc)に切り替えるか、[Go GCチューニング](/research/gogc-tuning)と **GOGC** の設定で Go を調整します。

### [高負荷下のJVMウォームアップ](/incidents/jvm-warmup)

- **兆候:** スパイクの間にオートスケーラーが足したコピーがランタイムの冷えた速度で答え、30 秒間 p99 が悪化します。
- **今すぐ:** 冷えたコピーの**ドレイン**を押します。[ヘルスチェック](/research/health-checks)が必要で、ノードが空になるとインシデントは終わります。そうでなければウォームアップを待ちます。
- **防ぐ:** ロードバランサーで**スロースタート**をオンにするか、[GraalVM ネイティブイメージ](/research/graal-native)をリサーチするか、[スケジュールスケーリング](/research/scheduled-scaling)でスケジュールに沿ってスケールします。

### [OPcacheの陳腐化](/incidents/stale-opcache)

- **兆候:** OPcache を使う忙しい PHP のアプリサーバーが、新しいスキーマに対して古いコードを動かし、リクエストの 30% を失敗させます。
- **今すぐ:** バナーまたはインスペクタの**再起動**を押します。キャッシュをリセットし、インシデントを終わらせます。
- **防ぐ:** [継続的デリバリー](/research/ci)をリサーチします。CI/CDパイプラインがデプロイのたびにキャッシュをリセットします。

### [ライブラリ非互換](/incidents/gevent-compat)

- **兆候:** 忙しい gevent のアプリサーバーがリクエストの 15% を失敗させます。
- **今すぐ:** バナーまたはインスペクタの**再起動**を押します。インシデントが終わります。
- **防ぐ:** [自動テスト](/research/testing-culture)をリサーチします。

### [ランタイム互換性](/incidents/bun-compat)

- **兆候:** 忙しい Bun のアプリサーバーがリクエストの 20% を失敗させます。
- **今すぐ:** バナーまたはインスペクタの**再起動**を押します。インシデントが終わります。
- **防ぐ:** [自動テスト](/research/testing-culture)をリサーチします。

### [スポット回収](/incidents/spot-reclaim)

- **兆候:** インスペクタに「プロバイダが N 秒後にこのスポットノードを回収します。オンデマンドに切り替えてください。」と出ます。10 秒後にノードが灰色になります。
- **今すぐ:** 警告が切れる前に**オンデマンドに切り替え**を押します。そうしなければインシデントが終わったときに自分で戻ります。
- **防ぐ:** リクエスト経路のノードはオンデマンドかリザーブドの料金に保ち、スポットはノードを失える群れにだけ使います。

### [不正なデプロイ](/incidents/bad-deploy)

- **兆候:** デプロイの直後にエラー率が跳ね、「不正なデプロイ」のバナーが**ロールバック**ボタンとともに出ます。
- **今すぐ:** バナーの**ロールバック**を押します。[継続的デリバリー](/research/ci)が必要で、なければ最大 120 秒で自然に終わります。
- **防ぐ:** [継続的デリバリー](/research/ci)と[自動テスト](/research/testing-culture)をリサーチします。カナリアのデプロイ戦略とフィーチャーフラグが、不正なデプロイの壊す範囲に上限をかけます。

### [不正な設定投入](/incidents/config)

- **兆候:** アプリサーバーとワーカーが一緒にクラッシュし、「不正な設定投入」のバナーが**ロールバック**ボタンとともに出ます。
- **今すぐ:** バナーの**ロールバック**を押します。古い設定で再起動します。
- **防ぐ:** [GitOps](/research/gitops)をリサーチし、段階的に適用して、プッシュがまず 1 つのリージョンに届くようにします。

### [接続枯渇](/incidents/connections)

- **兆候:** データベースのカードに「N queries/s を拒否: 接続が多すぎます。」と出ます。
- **今すぐ:** アプリサーバー側では終わらせられず、最大 40 秒で自然に終わります。アプリサーバーとデータベースの間の[コネクションプーラー](/components/pooler)が、保持する接続に上限をかけます。
- **防ぐ:** [コネクションプーリング](/research/pooling)をリサーチし、データベースの手前にコネクションプーラーを置きます。

### [サプライチェーン侵害](/incidents/supply-chain)

- **兆候:** 評判が落ちてユーザーが一斉に 10% 減り、「サプライチェーン侵害」のバナーが**固定して再デプロイ**ボタンとともに出ます。
- **今すぐ:** バナーの**固定して再デプロイ**を押します。
- **防ぐ:** [依存関係スキャン](/research/dependency-scanning)か [Deno](/research/deno)をリサーチします。セキュリティチームがさらに確率を下げます。

### [うるう秒と時刻ずれ](/incidents/leap-second)

- **兆候:** アプリサーバーのリージョンのすべてのノードが 1,000 ms 遅く答え、その応答の 10% がタイムアウトします。**ノードを再起動**ボタンのバナーが出ます。
- **今すぐ:** バナーの**ノードを再起動**を押します。1 クリックでリージョン全体が時刻を合わせ直します。
- **防ぐ:** [リープスミアリング](/research/leap-smearing)をリサーチします。

## ヒント

- インスタンスの系統をランタイムに合わせます。CPU バウンドのランタイムには Compute、ワーカーが多いなら Memory です。
- リークするサーバーを再起動してメモリを解放します。コールドで戻ります。

:::Note{tone="real"}
状態を持たないサーバーはコピーしやすいです。実際のチームがまずこれを横に広げるのはそのためです。[垂直と水平のスケーリング](/glossary/vertical-and-horizontal-scaling)を参照してください。
:::
