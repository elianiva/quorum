Claude Code や Codex のようなコーディングエージェントに自分の会社を読ませ、何を直すべきか教えてほしいときにこのガイドを使います。

Quorum は読み取り専用の [MCP](https://modelcontextprotocol.io) のエンドポイントを `https://playquorum.dev/mcp` で提供します。**エージェントアクセス**がオンのあいだ、ブラウザが開いている会社のスナップショットを数秒ごとにアップロードし、エンドポイントは最後のアップロードから答えます。エージェントはボード、インシデント、受信箱を読めますが、ノードを置くことも、ボタンを押すことも、設定を変えることもできません。

## 始める前に

- Streamable HTTP でリモートの MCP サーバーに対応したエージェント。
- [playquorum.dev](https://playquorum.dev) で開いている会社。

## エンドポイントをエージェントに追加する

1. サーバーを追加します。Claude Code では次を実行します。

   ```sh
   claude mcp add --transport http quorum https://playquorum.dev/mcp
   ```

   Codex では、これを `~/.codex/config.toml` に追加します。

   ```toml
   [mcp_servers.quorum]
   url = "https://playquorum.dev/mcp"
   ```

2. エージェントを起動します。インストールの手順も、ローカルのポートも、キーもありません。

## エージェントアクセスをオンにする

1. **Esc** でゲームのメニューを開き、**設定**を選びます。
2. **エージェントアクセス**をオンにします。既定ではオフで、ゲームは自分の選択を覚えています。
3. スイッチの下の**エージェントルーム**の ID をコピーします。

ID はスナップショットの名前で、パスワードではありません。書き込みのキーは自分のブラウザに残るので、ID を知る別の人は会社を読めますが、エージェントが見るものを置き換えることはできません。エージェントアクセスをオフにすると、スナップショットが削除されます。

## エージェントに尋ねる

1. 質問に ID を入れます。たとえば「エージェントルーム `abcDEFghiJKLmnoPQRstuv` を読んで、まず何を直すべきか教えてください。」
2. エージェントが `get_status` を呼び、そのあと `get_company` を呼ぶことを確認します。ステータスはスナップショットがどれだけ古いかを示します。答えが自分の資金、ユーザー、時代を示すなら、接続は動いています。

:::Note{tone="tip"}
エージェントには、指示だけでなく説明も求めます。「なぜデータベースがボトルネックなのですか」は「どこをクリックすればよいですか」より多くを教えてくれます。
:::

エージェントには 8 つのツールがあり、どれも読むだけです。

| ツール          | 返すもの                                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------------- |
| `get_status`    | スナップショットが最後に同期した時刻、モード、どれだけ保持しているか。最初に呼びます。                                |
| `get_company`   | 資金、ユーザー、Apdex、時代、レイテンシのパーセンタイル、売上、支出、ボトルネック、自分のリサーチ。ここから始めます。 |
| `get_design`    | 各ノードと、その流入と流出のリンクおよびそのレート、現在の負荷、破棄、各種別の健全さ。                                |
| `get_incidents` | 動いているインシデント、アラートのルールとアラーム、最近のポストモーテム。                                            |
| `get_inbox`     | 自分のメールと、各メッセージが示す選択肢。エージェントは選択肢を読めますが、選ぶことはできません。                    |
| `get_history`   | ユーザー、売上、支出、レイテンシ、p99、Apdex、エラーの最近のサンプル。傾向を見るためです。                            |
| `explain_node`  | あるノードがなぜ忙しいか。その負荷の変化、背後のトラフィック、それを明らかにするリサーチ。                            |
| `get_game`      | 保存されたゲーム全体を JSON で。大きいので、エージェントはほかを選ぶべきです。                                        |

サーバーは wiki もリソースとして提供します。`quorum://wiki/index` がそれらを並べます。リクエストの流れ、レイテンシ、エラーとリトライ、インシデント、資金、そして各コンポーネントのページです。ページを読んだエージェントは、推測ではなくゲーム自身のルールで自分の設計を説明できます。設計ドキュメント、パターン、リファレンスのページはウェブサイトに留まります。

どのツールもルーム ID を `room` の引数に取ります。エージェントは最後のアップロードを読むので、答えを自分の見ているものと合わせたいならゲームを一時停止します (**Space**)。タブを閉じても、最後のスナップショットは 24 時間残ります。

## 助言は自分で適用する

1. エージェントが勧めることを読みます。
2. 動く前に、ボードでその主張を確かめます。たとえば、名指されたノードを選んで**負荷**の行を読みます。これは[ボトルネックを見つける](/guides/find-the-bottleneck)が詳しく扱っています。
3. 変更は自分で行い、そのあとエージェントに会社をもう一度読むよう頼みます。

## 答えがないとき

| エージェントからのメッセージ                       | 直し方                                                                                                 |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| "Pass the agent room id shown in Quorum Settings…" | **エージェントアクセス**の下の ID をコピーし、質問に入れます。                                         |
| "This Room has no snapshot yet…"                   | 会社を開き、**エージェントアクセス**をオンにします。                                                   |
| "A Challenge is open."                             | チャレンジは採点されるので、どのエージェントも読めません。先にチャレンジを離れます。                   |
| 数値がゲームより古い                               | タブが閉じているか眠っています。前面に出します。最後のスナップショットは新しいものが来るまで残ります。 |
| "No Room is open…"                                 | 会社を開きます。                                                                                       |

## エージェントが接続できないとき

**設定**を開き、**状態をJSONでコピー**を選びます。結果をエージェントに貼り付けます。JSON はツールが返すのと同じビューを持ち、チャレンジが開いているあいだは同じく何も答えません。ゲームが変わるたびにコピーし直します。
