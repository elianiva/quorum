Infrastructure as code はインフラをレビュー済みのファイルに保ち、GitOps はリポジトリを変更を適用する唯一の場所にします。

## 使うとき

- 複数の環境やリージョンを動かし、それらが一致していなければならないとき。
- 手作業のコンソール操作が、誰にも説明できない障害を起こしたとき。
- 障害時にリージョンをゼロから作り直す必要があるとき。

## 仕組み

3 台のサーバーとデータベースといった望ましい状態を、Terraform や Pulumi のようなツールで書きます。ツールはそれを実際の状態と比べ、何を作り、変え、壊すかの計画を出力します。計画をレビューして適用します。GitOps はさらに進みます。Argo CD のようなエージェントが Git リポジトリを見張り、クラスタをそれに合わせ続けるので、プルリクエストのマージがデプロイになります。ドリフトとはファイルの外で行われた変更のことで、エージェントはそれを巻き戻すか報告します。

## コスト

リポジトリの悪い変更は、それに従うすべての環境へ速く届きます。1 つのリージョンを先にする段階的なロールアウトがそれを抑えます。状態ファイルと認証情報は機密で、誰も読まない計画はレビューになりません。インシデント中の手作業の修正は、あとで片付けるべきドリフトを生みます。

## Quorum では

ゲームにはこれ用のノードやリンクの設定がないので、設計もありません。[Infrastructure as Code](/research/infra-as-code) では IaC ツールを選び、あるリージョンのミラーを別のリージョンに作り、同期を保つために計画を適用できます。ツールは計画が手作業の変更をどう見つけるかを決めます。[GitOps](/research/gitops) はミラーを自力で同期し、一斉に、あるいは段階的に行います。[不正な設定投入](/incidents/config) インシデントが、段階的にすることがなぜ大事かを示します。用語集は [ミラー](/glossary/mirror)、[構成ドリフト](/glossary/drift)、[IaCツール](/glossary/iac-tool)、[GitOps](/glossary/gitops) を定義しています。
