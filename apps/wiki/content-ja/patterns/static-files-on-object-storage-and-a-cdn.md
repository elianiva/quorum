オリジンの手前に CDN を置き、アップロードされたファイルはオブジェクトストレージに保ちます。

## 移行するとき

- ページビューと動画がアプリサーバーの CPU の大半を食い、エグレスの行が大きいとき。
- 世界中のすべてのユーザーが、1 つのオリジンへの往復を待つとき。

## なぜ効くのか

CDN のヒット率は、自分のサーバーに触れずに答えたページビューの割合です。アプリサーバーとデータベースの負荷バーが下がり、ヒットがユーザーの近くで返るので p99 も一緒に下がります。

2 つの設定が効きます。長い TTL はヒット率を上げ、デプロイ時にパージはリリース時にエッジを空にするので、誰も古いページを見ません。含むものが少ないキャッシュキーはヒットをさらに増やしますが、あるユーザーのページが別のユーザーに漏れることがあります。

## コスト

CDN は API の読み取り、書き込み、ログイン、チェックアウトをキャッシュしません。パージなしの長い TTL は、デプロイ後に古いページを配ります。パージはエッジが埋まる間、オリジンにミスのバーストを負わせます。オブジェクトストレージの読み取りは、データベースのクエリより最初のバイトまで長く待ちます。
