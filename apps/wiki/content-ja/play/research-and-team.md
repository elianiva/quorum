`R` を押すとリサーチが開き、研究にインサイトを使います。`T` を押すとチームが開き、機能に開発時間を使います。どちらのパネルもボードを覆い、`Esc` で閉じます。

## リサーチのパネル

リサーチのボタンは右上のツールバーにあります。インサイトが項目の支払いに足りたときに初めて現れ、バッジが払える項目を数えます。それまでは `R` は何もしません。

![リサーチのパネル。左にツリー、右に詳細のサイドバー](/play/research-panel.png)

見出しのチップを見ます。各チップは1つのインサイトのプールと手持ちの量です。次にツリーを見ます。各トラックは根から上へ伸び、時代ごとに1つの帯があります。トラックはインフラ、データ、信頼性、可観測性、パフォーマンス、ランタイム、フレームワーク、セキュリティ、プロダクト、コストです。

### 項目を読む

項目をクリックするとフォーカスします。右の詳細のサイドバーは次を示します。

- **コスト**: その項目のレシピのプールごとに1行。各行にコスト、**保有**している量、プールが毎秒稼ぐレートが出ます。琥珀色の保有量はまだ払えないという意味です。プロダクトレバーのある種別は、その行にレバーも示します。段階、その種別が取るトラフィックの割合、**ビルド**ボタンです。
- **必要条件**: 先に持っていなければならない項目。クリックするとそこへ飛びます。
- **解放するもの**: その項目が開くもの。

サイドバーの主なボタンが、いまできることを示します。

| ボタン           | 意味                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| **研究を開始**   | 開始できます。ボタンには所要時間も出ます。                                                                         |
| **研究中 · n%**  | いま走っています。                                                                                                 |
| **今すぐ研究**   | キューで待っています。選択すると、待っている前提とともに先頭へ移ります。                                           |
| **◯◯後に解放**   | 時代がまだ始まっていません。                                                                                       |
| **◯◯の後に研究** | 前提が欠けています。選択すると欠けた前提を先にキューへ入れ、そのあとに項目を入れます。ボタンがその名前を示します。 |
| **研究済み**     | 持っています。                                                                                                     |

ロックされた項目はエラーではありません。次にすべきことを示します。時代を待つか、キューに入れて前提を先に走らせます。長い連鎖が欠けているときは、ボタンは前提を名指しせず数えます。サイドバーの警告が研究の待ち先を示します。何も稼がないプールか、設計がまだ示していない形です。一度もヒットしないキャッシュや、仕事のあまりを読み取りに使わないデータベースなどです。サイドバーは設計が要件からどれだけ離れているかを**60% のうち 47%**のように示し、**キューに追加**は要件を満たしたときに始まるよう項目をキューへ入れます。連鎖なら、待つ最初の研究を名指しします。プールは上限で満ちるのを止めるので、それ以上ためたインサイトは何も稼ぎません。インサイトがどこから来るかは[インサイトを稼いでリサーチする](/tutorials/research-and-insight)を読んでください。

### 研究を始めてキューに入れる

1. `R` を押します。
2. ボタンが**研究を開始**と出る項目をクリックします。
3. **研究を開始**を選択します。HUD のインサイトのカードが研究の名前と割合を示します。
4. `Esc` を押してボードへ戻ります。研究は走り続けます。

さらにキューに入れるには、別の項目を選んでそのボタンを選ぶか、ツリーでダブルクリックします。キューは8件の研究を保ち、連鎖はその中のすべての研究を数え、先頭の払えない研究が後ろのすべてを止めます。それはサイドバーが告げます。各キューの行には**上へ**、**下へ**、**キャンセル**のボタンがあり、行を新しい場所へドラッグもできます。**キャンセル**は進み具合を失います。

研究が、必要とする前提より上へ動くことはありません。**上へ**のボタンはオフになり、前提を越えるドラッグは拒否され、トーストがそれを名指しします。前提をキャンセルすると、それを必要とするキューの研究もキャンセルされます。

### プールの供給を増やす

研究に追いつけないプールはそれを遅くし、直し方はサンプルを増やすことではなくプロダクトの変更であることもあります。走っている項目を開くと、**プロダクトレバー**のある種別はコストの行の下にそれを示します。

1. プールの行の下のカードを読みます。プールが研究を制限しているときは、タイトルがその種別のインサイトが低すぎると告げ、その下の行が両方のレートを示します。プールが毎秒稼ぐ量と、研究が要求する量です。最後の行は、次の段階がトラフィックの割合でどこまで届くかと、ユーザーの成長で何を犠牲にするかを示します。
2. **ビルド**を選択します。その段階が、その段階の開発時間とともにチームのバックログに加わり、チームがそこに開発時間を使います。
3. 項目が**出荷中**に届くまでチームのパネルを見ます。デプロイが着地すると種別の割合が上がり、そのプールは速く稼ぎ、カードが次の段階を差し出します。時代がまだ開いていない段階は灰色のままで、カードがどの時代で開くかを告げます。
4. 段階を1つ戻すには**削除**を選択します。最後の段階を取り除き、その開発時間の半分を返し、割合はほかの種別へ戻ります。

すでにバックログにある段階、事業の上限、ロックされた配合は、それぞれボタンを灰色のままにし、その下に理由を出します。チャレンジは配合を固定するので、レバーのカードをまったく出しません。

## チームのパネル

チームのボタンは最初の機能が出荷されたあとに現れます。琥珀色の点はバックログが空という意味です。数字の裏のルールは[チームとベロシティ](/explanation/team-and-velocity)を読んでください。

![チームのパネル。左にサービスとチーム、右にボードと機能](/play/team-panel.png)

見出しは開発時間の残高、毎分のレート、毎秒の人件費を示します。パネルは2つの半分に分かれます。

### フロア（左）

フロアはチームごとに1枚のカードを示します。各カードは**創業者**（「あなた」と表示）から始めてエンジニアを並べます。各エンジニアは毎秒の給料を示すか、新しければ**立ち上がり中**と示します。

1. 空いた席の**採用**を選択します。席のラベルは言語を示し、たとえば「Python エンジニアを $x で採用」です。プレシードまでは**ロック中**と表示され、採用の費用を払えないときは灰色になります。
2. エンジニアを動かすには、別のチームへドラッグするか、そのカードの移動ボタンを使います。
3. エンジニアに、サービスが動く言語、またはマイグレーションが移ろうとしている言語を教えるには、そのカードにホバーして**学ぶ**ボタンを使います。ボタンは言語と価格を示します。エンジニアはリングが満ちるまで半分の速度で働き、そのあと言語を身につけます。払えないときはボタンが灰色になります。
4. 誰かを解雇するには、そのカードにホバーして**解雇**ボタンを使います。
5. **新しいチーム**を選択してチームを加えます。チームには種類があります。プロダクト、プラットフォーム、SRE、データ、セキュリティです。

プロダクトのチームには3つのポリシーがあります。**速度優先**、**バランス**、**品質優先**です。速さと、負債と不正デプロイを引き換えにします。ほかの種類はシステムを動かし、機能は作りません。SRE はページャーを持ち、データはウェアハウスを動かし、プラットフォームはクラスターとデプロイを動かし、セキュリティは WAF のルール、依存関係のスキャン、コンプライアンスを動かします。速くなるために早く採用すると裏目に出ます。エンジニアが増えるほど人件費が毎秒かかり、大きなチームは調整で遅くなるからです。要らないチームを採用する前に[チームとベロシティ](/explanation/team-and-velocity)を読んでください。

8人のエンジニアのチームは仕事を始めるのを止めます。始める項目はどれも承認を待ち、チームのボードが**あなたの判断待ち：チームが大きすぎる**と告げます。項目を承認するか、エンジニアを別のチームへ移します。Core では創業者が余分な1人なので、Core は9人で待ちます。

### ボード（右）

ボードには4つの列があります。**次**、**進行中**、**出荷中**、**稼働中**です。

1. **機能**の下のタイルを探します。**ビルド**を選択してバックログに加えます。
2. それが**進行中**へ移るのを見ます。チームがそこに開発時間を使います。
3. 終わった項目は**出荷中**で待ちます。デプロイのカードが**◯◯後にデプロイ**と時間を示し、そのあと機能は**稼働中**になります。
4. バックログの項目の稲妻のボタンで、開発時間を使って**急ぎ**ます。急いだ仕事はいま終わり、そのサービスに技術的負債を加えます。プレシードからは、急いだ機能はデプロイがバグを出す可能性が高くなります。**キャンセル**で取り下げます。

**エンジニアリング**の下では、タイルの**キューに入れる**を選んで技術的負債を返すか、リークを直します。直すものがあるときに行が現れます。

デプロイのカードは**不正デプロイ ◯%**の行も示します。高い数字は、デプロイがアプリサーバーを壊すかもしれないという意味です。次のページの不正デプロイの帯が、その巻き戻し方を示します。

### オートパイロット

ボードの見出しの**オートパイロット**のスイッチは、バックログの自動モードを入れます。バックログが2件になると現れます。さらに3つのスイッチは、オートパイロットのパークがその段階にあるときだけ現れます。

- **一番安い研究をキューに入れる**
- **人件費が売上の4分の1未満なら採用する**
- **負荷70%以上のアプリサーバーの次のサイズを買う**

パークは[レガシー](/explanation/legacy)の買い物なので、新しい会社ではどれも出ません。
