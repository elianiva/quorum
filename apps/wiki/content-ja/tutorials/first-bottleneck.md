このレッスンでは、自分の設計を制限しているノードを見つけ、その理由を突き止めて直します。ガレージでは
越えるべき限界が2つあります。まずメモリ、次に CPUクレジットです。[最初の会社](/tutorials/first-company)
で作った会社から始めます。

## 最初の限界を待つ

1. ゲームを動かしたまま、売上を回収します。
2. アプリサーバーのカードを見ます。数百ユーザーになると**負荷**の行が跳ね上がり、行が琥珀色か
   赤になります。
3. アプリサーバーを見ます。輪郭が琥珀色に脈打ち始めます。

ボトルネックは、いま自分の売上を最も多く奪っている1つのノードです。ゲームがそれをどう見つけるかは
[リクエストの流れ](/explanation/requests)にあります。

マシンが初めてボトルネックになったとき、カード下部のサイズ変更ボタンが光ります。まだクリックしません。
まず、マシンがなぜいっぱいなのかを調べます。

## 原因を読む

1. アプリサーバーを選択します。インスペクタが開きます。
2. タイトルの下の赤い枠を読みます。**RAMが尽きてスワップ中：すべてのリクエストが遅くなります。**と
   書かれています。
3. **リソース**のセクションを探します。**RAM**のゲージが満杯です。

アプリサーバーと PostgreSQL は1台のマシンを共有しています。ユーザーが増えるほどデータベースは多くの
データをメモリに置くので、マシンの RAM が尽きます。メモリをディスクへ移しますが、これをスワップと
呼び、すべてのリクエストが遅くなります。HUD では**Apdex**が目標を下回り、**ユーザー**に ▼ が付きます。
待っている間にユーザーが離れるためです。

## データベースを専用のノードへ移す

最初の修正は、データベースに専用のマシンを与えることです。多くのチームが早い段階でそうします。

1. 画面下部の建設ドックで**データ**グループを選択します。番号キーを押してもかまいません。1回選ぶと
   部品が1つ選択待ちになるので、ノードを置くたびに選び直します。
2. 一覧から**データベース**を選択します。価格は行の右側に表示されます。
3. アプリサーバーの右のボードをクリックします。データベースのカードが現れます。
4. アプリサーバーのカードにある青い出力ポートを探します。
5. そのポートからデータベースのカードへドラッグします。リンクが現れます。あとでリンクを切るには、
   リンクをクリックし、その上に現れる**x**をクリックするか、**Delete**を押します。

最初のマシンをデータベースにリンクすると、PostgreSQL はそのマシンから完全に移ります。もう一度
アプリサーバーを選択します。赤い枠は消え、**RAM**のゲージは満杯から遠くなっています。

ここで30秒ほど HUD を見ます。

- **Apdex**が目標を上回るところまで戻ります。
- **ユーザー**に再び ▲ が付きます。
- 輪郭はアプリサーバーから離れるか、どのノードにも付かなくなります。

間違えたときは **Z** を押して元に戻します。30秒以内の元に戻す操作は、費用の全額が返金されます。

:::Note{tone="real"}
アプリとデータベースを1台のマシンで動かすのは、ほとんどのプロダクトが始める形です。データベースを
外へ移すのは古典的な最初のスケーリング手順です。それぞれの部分を個別に育てられます。
:::

## 2つ目の限界を待つ

アプリサーバーはバースト可能なマシンです。アイドルの間に CPUクレジットを貯め、高負荷のときに
使います。クレジットが尽きると、マシンは CPU のごく一部でしか動きません。

1. ゲームを動かしたままにします。売上を回収します。
2. ときどきアプリサーバーを選択します。**リソース**の**CPUクレジット**のゲージを見ます。
   トラフィックが増えるにつれて下がります。
3. ゲージが空になると、インスペクタに**CPUクレジットが尽きました：CPUは20%に制限されています。**と
   表示されます。

**負荷**の行が赤くなり、輪郭がアプリサーバーに戻ります。

## バースト可能から離れる

1. アプリサーバーを選択します。
2. インスペクタの**インスタンス**セクションを探します。5つのファミリーが表示されます。
   **バースト可能**、**汎用**、**コンピューティング**、**メモリ**、**ARM** です。ARM には
   リサーチが必要です。
3. **汎用**を選択します。
4. トレードオフのカードが開いたら、プレビューを読んで**確定**を選択します。

マシンは少しの間再起動するので、トラフィックが一瞬落ちます。その後**CPUクレジット**のゲージは消え、
**負荷**の行も下がります。汎用のマシンはバースト可能より1秒あたりの費用が高いですが、制限される
ことはありません。

マシンを大きくすることもできます。**インスタンス**セクションで**大きくする**を選択するか、ノードを
選択した状態で **U** を押します。大きなマシンは CPU と RAM が増え、価格も上がります。これが
[垂直スケーリング](/glossary/vertical-and-horizontal-scaling)です。

カード下部のサイズボタンは、0.6秒ほど押し続けたときだけ購入されます。素早くクリックしても何も
起きません。押し続けると、さらに大きなサイズを購入できます。

2つのガイド付きサンドボックスが、固定のボードでこのレッスンを繰り返します。
[クレジット切れ](/sandboxes/out-of-credits)と[相乗りボックス](/sandboxes/shared-box)です。
[リクエストの流れ](/explanation/requests)では、いま2度たどったユーザーからデータへの道のりを
説明します。[最初のインシデント](/tutorials/first-incident)は、この会社がプレシードラウンドを
調達した瞬間から始まります。
