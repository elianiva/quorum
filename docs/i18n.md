# Interface languages

The website supports English (`en`), French (`fr`) and Simplified Chinese (`zh-CN`). English is
the default and the fallback for untranslated text. The language dropdown is in
Settings on the board. The existing browser preferences store remembers
an explicit choice; older preferences decode as English.

Language belongs to the web Model and preferences, not Game, the Simulation, RPC,
replays or company saves. `LocaleChosen` persists the preference, sets the document
language and synchronizes the Pixi board, including while paused.

The English source copy is the message identifier. `src/i18n/fr.ts` and
`src/i18n/zh-CN.ts` contain the respective dictionaries. French glossary and mail
copy live in `fr-glossary.ts` and `fr-mail.ts`. Only complete messages match; numbered placeholders represent
dynamic values. Unknown messages retain their original text. Product names,
protocol names, currency and engineering abbreviations remain unchanged. French
uses Go for gigabytes; monetary values retain the game's dollar denomination.
Dynamic patterns are compiled separately for each language, with specific messages
matched before generic ones. Captured catalog names are translated recursively,
including lists of known labels; unknown prose keeps the English fallback.

HTML localization is a pure presentation pass over the freshly constructed view:
text and title/alt/placeholder/aria-label attributes only. Keys, event handlers,
URLs, IDs, input values and data attributes are preserved. It never rewrites the
live DOM. Pixi uses the same translator at its text assignment sites, with locale
included in its rendering digest. No mutable global locale is used.

Checks cover preferences from older versions, switching without changing Game,
board synchronization, fallback/interpolation, and preservation of VNode identity
and event handlers. Browser acceptance covers all languages, refresh, settings,
menus and the board. New copy needs a corresponding dictionary entry; untranslated
copy is safe to display but is not considered translated.

All locales traverse the same view-copy path so Foldkit-generated identities stay
stable and language changes do not remount the live board or reset its camera.
Browser acceptance checks canvas identity and visible cards when switching between languages
while paused.

French covers menus, HUD, the Pixi board, component controls, research, team and
deployment controls, funding, exits, challenges, tutorials, achievements, alerts,
Dashboard, every glossary definition and in-game explanation, and every variant of
the narrative mail, including spam and conditional security advisories. Fictional
sender names, CVE IDs and stack names keep their original spelling. Mail stays in
its original English form in the web Model and is translated when displayed, so existing threads also
switch language. No translation service is contacted at runtime.

Chinese coverage includes menus, HUD, component controls, research, tutorials and
the searchable glossary. Long randomized mail and story prose currently retain
the English fallback.

The dropdown uses Foldkit Listbox and the `supportedLocales` registry.
It matches the title screen’s scoped dark palette and the board’s light palette.
The Chinese UI calls the Pre-seed stage 天使轮 and the Seed stage 种子轮.

## Upstream integration and language picker

The upstream Dashboard, glossary category filter and expanded sourced explanations
keep their behavior. Glossary search combines the category filter with English
and translated term, definition and in-game explanation text, ignoring accents
for French keyboard input. Expanded Chinese glossary
prose and new Dashboard copy may fall back to English until translated; the
previous coverage statement is not a claim that these additions are complete.
Board text must be translated before upstream width fitting, with locale retained
in the rendering digest so switching while paused updates the existing canvas.

The language picker uses the installed Foldkit Listbox with project theme
classes for both the trigger and options. Its transient interaction state belongs
only to the web Model; selected locale still follows `LocaleChosen` and the existing
preferences contract. Options come from `supportedLocales`. The dropdown opens
downward from Settings and portals outside its clipped panel. Foldkit
owns keyboard navigation, typeahead, dismissal and focus restoration. Game hotkeys
must ignore listbox interactions. Acceptance covers mouse and keyboard selection,
Escape and outside dismissal, selected state, refresh persistence, both palettes,
compact screens and paused-board canvas identity. French tests check all catalog
presentation fields, every mail variant, placeholders, nested labels, accents in
search, preference persistence and unchanged Game state.
