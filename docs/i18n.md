# Interface languages

The website supports English (`en`), French (`fr`), Simplified Chinese (`zh-CN`), Japanese
(`ja`) and Spanish (`es`). English is the default and the fallback for untranslated text. The
language dropdown is in Settings on the board. The existing browser preferences store remembers
an explicit choice; older preferences decode as English.

Language belongs to the web Model and preferences, not Game, the Simulation, RPC,
replays or company saves. `LocaleChosen` persists the preference, sets the document
language and synchronizes the Pixi board, including while paused.

The English source copy is the message identifier. Each language is a directory of the same
modules under `src/i18n/` — `en/`, `fr/`, `zh-CN/`, `ja/` and `es/` — with `mail.ts` for every letter.
The catalog tables live in `packages/ui/src/i18n/catalog/<language>.ts`, so the wiki reads the same words. Only complete messages match; numbered placeholders
represent dynamic values. Unknown messages retain their original text. Product names,
protocol names, currency and engineering abbreviations remain unchanged. French
uses Go for gigabytes; monetary values retain the game's dollar denomination.
Spanish uses GB and keeps the Simulation's number format: commas between thousands,
a dot before decimals, and no space before a percent sign.
Design change labels, such as "Raised the Search lever", stay English in the Model and the undo history, are written from `en.changes`, and `changeIn` translates them on display.
Dynamic patterns are compiled separately for each language, with specific messages
matched before generic ones. Captured catalog names are translated recursively,
including lists of known labels; unknown prose keeps the English fallback.

HTML localization is a pure presentation pass over the freshly constructed view:
text and title/alt/placeholder/aria-label attributes only. Keys, event handlers,
URLs, IDs, input values and data attributes are preserved. It never rewrites the
live DOM. Pixi uses the same translator at its text assignment sites, with locale
included in its rendering digest. No mutable global locale is used.

Checks cover preferences from older versions, switching without changing Game,
board synchronization, fallback/interpolation, and preservation of VNode identity
and event handlers. Browser acceptance covers all languages, refresh, settings,
menus and the board. New copy needs a corresponding dictionary entry; untranslated
copy is safe to display but is not considered translated.

All locales traverse the same view-copy path so Foldkit-generated identities stay
stable and language changes do not remount the live board or reset its camera.
Browser acceptance checks canvas identity and visible cards when switching between languages
while paused.

French covers menus, HUD, the Pixi board, component controls, research, team and
deployment controls, funding, exits, challenges, tutorials, achievements, alerts,
Dashboard, every glossary term name, and every variant of
the narrative mail, including spam and conditional security advisories. Fictional
sender names, CVE IDs and stack names keep their original spelling. Mail stays in
its original English form in the web Model and is translated when displayed, so existing threads also
switch language. No translation service is contacted at runtime.

Chinese coverage includes menus, HUD, component controls, research, tutorials,
Dashboard, company management, every catalog field, and every glossary term name. Narrative mail
subjects and every paragraph variant translate in both previews and the Inbox,
including funding, alerts, spam and security advisories. Existing stored English
mail switches language on display. Fictional sender names and technical identifiers
retain their spelling. CSS, URLs and internal identifiers are not translation copy.

Japanese has the same coverage as French and Chinese: menus, HUD, the board's node
names, component controls, research, team and deployment controls, funding, exits,
challenges, tutorials, achievements, alerts, Dashboard, every catalog field and
glossary term name, and every variant of the narrative mail, including spam and security
advisories. Engineering terms keep the form Japanese engineers write rather than a
literal translation: キャッシュスタンピード, サーキットブレーカー and ヘッジリクエスト
stay in katakana, and pattern and paper names such as The Tail at Scale, Power of
two choices and Expand/Contract keep their English spelling. The game's own nouns
follow one table: Research is リサーチ, a Study is 研究, a Node is ノード, a Component
is コンポーネント. Each sender keeps its register — cloud notices use business 敬語,
alerts use 体言止め and lists, teammates write casually. Japanese has no plural form,
so no dictionary has a singular or plural branch. Mail stays English in the web
Model and translates on display, so existing threads switch language too.

The dropdown uses Foldkit Listbox and the `supportedLocales` registry.
It matches the title screen’s scoped dark palette and the board’s light palette.
The Chinese UI calls the Pre-seed stage 天使轮 and the Seed stage 种子轮; the Japanese
UI calls the Pre-seed round プレシード and the Seed round シード; the Spanish UI calls
them Pre-semilla and Semilla. Spanish has the same coverage as French, Chinese and
Japanese: menus, HUD, the board's node names, component controls, research, team and
deployment controls, funding, exits, challenges, tutorials, achievements, alerts,
Dashboard, every catalog field and glossary term name, and every variant of the
narrative mail, including spam and security advisories. The interface and teammates
address the player as `tú`; cloud providers, vendors and security notices use
`usted`, and alerts stay impersonal. Engineering terms use the words Spanish
engineers write: `circuit breaker`, `stack`, `failover` and `service mesh` keep their
English form, and pattern and paper names such as The Tail at Scale and
Expand/Contract keep their spelling. The game's own nouns follow one table: Research
is Investigación, a Study is Estudio, a Node is Nodo and a Component is Componente.
Mail stays English in the web Model and translates on display, so existing threads
switch language too.

## Upstream integration and language picker

The upstream Dashboard keeps its behavior. The game links each glossary term to its
wiki page, the Spanish one when it is played in Spanish and the English one otherwise, so a
term name is the only glossary copy the interface needs. Chinese, Japanese and Spanish include the Dashboard copy. Unknown future copy still
falls back to English.
Board text must be translated before upstream width fitting, with locale retained
in the rendering digest so switching while paused updates the existing canvas.
A board label that does not fit its room is drawn smaller, down to 72% of its own
size, before it is cut with an ellipsis; Pretext measures each label from its font,
so fitting never reads back a rendered texture. A Research card name takes a second
line before it ellipsizes, and Japanese breaks there at a phrase boundary where the
browser supports it.

The language picker uses the installed Foldkit Listbox with project theme
classes for both the trigger and options. Its transient interaction state belongs
only to the web Model; selected locale still follows `LocaleChosen` and the existing
preferences contract. Options come from `supportedLocales`. The dropdown opens
downward from Settings and portals outside its clipped panel. Foldkit
owns keyboard navigation, typeahead, dismissal and focus restoration. Game hotkeys
must ignore listbox interactions. Acceptance covers mouse and keyboard selection,
Escape and outside dismissal, selected state, refresh persistence, both palettes,
compact screens and paused-board canvas identity. Shared coverage tests check all
catalog presentation fields, every mail variant and placeholder preservation in
French, Chinese, Japanese and Spanish. Chinese view regressions cover existing
funding mail in both the preview and Inbox and newly composed labels. Japanese view
regressions cover existing funding mail in both the preview and Inbox. Spanish view
regressions cover existing funding mail in both the preview and Inbox. Other
language checks cover nested labels, preference persistence and unchanged Game state.

## Wiki

The wiki is in English and Spanish. English stays at the root and Spanish lives under `/es` with the
same slugs, so `/glossary/cache-stampede` and `/es/glossary/cache-stampede` are one page in two
languages. A page's language comes from its URL prefix; its logical path never carries the prefix.

Interface copy is `apps/wiki/src/i18n/en/` and `es/`. Spanish is typed as the English shape, so a
missing key fails typecheck. Catalog words (names, blurbs, causes) come from
`@quorum/ui/i18n/catalog/<language>`, the tables the game reads, laid over the Simulation's tables;
a field with no Spanish text keeps its English text. Spanish glossary entries carry their
definition and in-game text, so `/es/glossary` pages read in Spanish. Spanish loads as a separate chunk
(`src/locales/es.ts`), so a reader of English never downloads it, and a link to the other language
loads the whole page.

Prose lives in `apps/wiki/content/` (English) and `apps/wiki/content-es/` (the same relative paths).
A Spanish file replaces its page's title, summary, aliases and body. Section, group, order, era, gdd
and toc always come from the English file. A page with no Spanish file shows its English text with a
notice. The design record and the changelog stay English. Edit on GitHub points at the Spanish file
when there is one.

A heading keeps its English slug as its anchor, paired by position with the English heading, so a
link such as `/es/patterns/one-box#how-it-works` works in both languages. If the counts differ, the
Spanish text is slugged with accents removed. The tests in `src/i18n.test.ts` check every file in
`content-es/` for its counterpart, headings, link targets, islands and frontmatter.

Every link a Spanish page draws is pointed into `/es` by its builder (`src/i18n/builder.ts`), so
prose and components write `/components/lb` and never name a language. Each language has its own
search index (`/search-index.json`, `/es/search-index.json`) with its own stop words and accent
folding. Pages carry `hreflang` alternates, `og:locale` and `inLanguage`, and the sitemap lists both
languages. The Markdown export (`llms.txt` and the `.md` pages) is English only. The game opens
`/es/glossary/<term>` when it is played in Spanish. The Practice boards show the game's English
refusal sentences, and the Design islands keep their English settings tables.
