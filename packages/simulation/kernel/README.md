# Solve kernel

The game's solve, written in Rust and compiled to `wasm32-unknown-unknown`. It takes a Game
and returns the Ledger and the Bottleneck. The crate has no `unsafe` code and no
dependencies.

`packages/simulation/src/kernel.ts` is the host side. It writes a Game into the kernel's
blocks and decodes the Ledger. The Simulation package names no host globals, so each host
loads the module and passes its exports to `installKernel`:

| Host              | Loads the module with                                         |
| ----------------- | ------------------------------------------------------------- |
| `host/node.ts`    | `readFileSync` on `@quorum/simulation/kernel.wasm`            |
| `host/browser.ts` | `fetch` on a `new URL(..., import.meta.url)` asset            |
| `host/worker.ts`  | a `.wasm` module import, which Workers compile at deploy time |

When no kernel is installed, the solve throws. There is no TypeScript fallback.

## Build

```sh
rustup target add wasm32-unknown-unknown   # once
cargo build --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/qsim.wasm ../src/kernel.wasm
```

The game loads `src/kernel.wasm`, which is committed. Rebuild and copy it after every change
to the crate. Before you commit, run these and make sure each reports 0 warnings:

```sh
cargo clippy --release --target wasm32-unknown-unknown
cargo clippy --release --tests
cargo test --release
```

After a catalog change, regenerate `src/catalog.rs` from the TypeScript catalog:

```sh
node gen-catalog.ts src/catalog.rs
```

## The ABI

The host and the kernel share named blocks in memory the kernel owns. The host calls
`reserve(block, length)`, writes through `ptr(block)`, and then calls one run function.
Each run function returns a status code from `src/abi.rs`, and 0 means OK. A short block,
an Edge that names a missing Node, or an unknown incident returns a code. The host never
reads a figure that only looks right.

| Export                                        | What it does                                                    |
| --------------------------------------------- | --------------------------------------------------------------- |
| `design_set`                                  | Compiles the Design's routing tables once, and caches them      |
| `solve_run`                                   | Runs the pass loop and writes the Ledger and the summary blocks |
| `bottleneck_run`                              | Runs the Bottleneck search on the last solve's Ledger           |
| `forget_solve`                                | Drops the cached solve, so the next search solves again         |
| `scalar_len`, `node_field_len`, `summary_len` | The block layouts, so the host can check them                   |

`kernel.ts` mirrors the block ids, the scalar slots, and the Ledger stream in
`src/wire.rs`. When one side changes, change the other too. `installKernel` checks the
scalar count and the Node row length, so a slot added on one side only fails at start.

## Layout

| File              | Owns                                                            |
| ----------------- | --------------------------------------------------------------- |
| `src/catalog.rs`  | Every catalog constant and table, generated by `gen-catalog.ts` |
| `src/dist.rs`     | The outcome algebra: success, latency, and failure shares       |
| `src/model.rs`    | Each Component's capacity model                                 |
| `src/routing.rs`  | The compiled Design and the routing splits                      |
| `src/pass.rs`     | The forward pass: arriving rates per Node and kind              |
| `src/outcomes.rs` | The outcome tree for each Users Node and request kind           |
| `src/ledger.rs`   | The Ledger figures                                              |
| `src/bill.rs`     | The bill and its cost lines                                     |
| `src/solve.rs`    | The pass loop, the convergence test, and the Bottleneck search  |
| `src/run.rs`      | The run functions                                               |
| `src/abi.rs`      | The blocks, the status codes, and the scalar row layout         |
| `src/wire.rs`     | The Ledger stream the host decodes                              |

`NOTES.md` records the Rust patterns the crate uses and the bugs the port found.

## Performance

These figures come from the 200-Node stress board on Apple Silicon. Each is a mean of 40
samples after warm-up, measured before the kernel replaced the TypeScript solve.

| Figure                          | TypeScript    | Rust          | Speedup |
| ------------------------------- | ------------- | ------------- | ------- |
| `solveFlow` (6 passes + Ledger) | 8,241 µs      | 790 µs        | 10.4×   |
| `bottleneckOf` (3 candidates)   | 2,522 µs      | 338 µs        | 7.5×    |
| `solve` (flow + search)         | 9,056 µs      | 1,064 µs      | 8.5×    |
| Ledger held                     | 448 KB (JSON) | 23 KB (block) | n/a     |

Before the TypeScript solve was deleted, a shadow run solved every Game in every test
suite with both implementations: 61,999 solves, and every figure was identical.

## Known limits

`gen-catalog.ts` cannot import two lists: `GLOBAL_COMPONENTS` from `regions.ts`, and the
per-Component zone lists, which are not exported. A change to either needs a manual edit
to the generator.
