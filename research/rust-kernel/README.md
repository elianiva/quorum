# Rust kernel research

An experiment: rewrite the `@quorum/simulation` solver in Rust, compile it to
`wasm32-unknown-unknown`, and measure it against the TypeScript package. This is
research code. No production code imports it.

The goal is bit-identical results to TypeScript on the same inputs. Every layer is
checked against a TypeScript harness that runs the same board through both
implementations and compares figures.

## Build

```sh
rustup target add wasm32-unknown-unknown   # once
cargo build --release --target wasm32-unknown-unknown
```

The wasm lands at `target/wasm32-unknown-unknown/release/qsim.wasm`. The harnesses
load it from there.

## Harnesses

Run with `node <file>.ts` (Node 26 strips types). Each one prints a match count and,
where relevant, a timing comparison.

- `gen-catalog.ts` writes `src/catalog.rs` from the TypeScript catalog. Re-run it
  after any catalog change.
- `fuzz-dist.ts` compares the outcome algebra on random inputs.
- `splits.ts` compares routing splits on even and uneven weights.
- `forward.ts` compares arriving rates and model figures for a board, with timings.
- `outcomes-check.ts` compares the outcome tree figure by figure.

## Measured so far

On the 200-node stress board: arriving rates 307 µs in Rust against 837 µs in
TypeScript, 2.73×. Graph building, topological ordering, and routing all live inside
that figure. Routing alone, in isolation, is slower than V8 because the work is tiny
and the boundary dominates.

## Open problems

- `outcomes.rs` diverges from TypeScript on figures downstream of an App Server:
  `page.success` 0.2256 against 0.25, `page.variable` about half of TypeScript's.
  The suspicion is the `(backend, count)` weighting inside `through`, not routing.
- `forward.ts` currently aborts in `forward_run` on a fresh checkout. Find the
  panic first; `cargo build` with a `panic = "unwind"` profile override and a debug
  build give a message.
- `gen-catalog.ts` emits `FLAT_CAPACITY` from the wrong source file; the constant in
  `catalog.rs` was patched by hand and the generator still needs the fix.
